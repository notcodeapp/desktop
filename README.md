# NotCode Desktop

NotCode Desktop — приложение для работы с кодом и локальными проектами. Это desktop IDE с редактором, проводником, терминалом, Git и AI-агентом. Приложение рассчитано на Windows 10/11; интерфейс сделан на React и TypeScript, системные операции — на Rust через Tauri 2.

## Что умеет приложение

- Открывать папку проекта, показывать дерево файлов и искать текст по проекту.
- Редактировать UTF-8 файлы в Monaco Editor, открывать несколько вкладок и разделять редактор на две панели. Размер файла для редактирования ограничен 1 MiB.
- Подключать AI через Ollama на локальном компьютере или через OpenAI-compatible HTTPS API.
- Просматривать дерево проекта, читать и искать файлы с помощью AI. Агент может создать папку, создать пустой файл, а затем записать в него содержимое. Создание и запись требуют отдельного подтверждения.
- Запускать PowerShell в терминале после подтверждения.
- Просматривать Git-статус, diff, историю и ветки, а также выполнять поддерживаемые Git-операции.
- Подключать локальные MCP-серверы через stdio, просматривать их инструменты и запускать инструменты после подтверждения.

## Как работает AI-агент

Для Ollama используется локальный адрес loopback и API чата Ollama. Для внешнего сервера задаются HTTPS-адрес, модель и API-ключ; ключ хранится в Windows Credential Manager. Выбранный сервер получает сообщения пользователя и содержимое файлов, которые агент читает или которые пользователь прикрепляет к сообщению.

Чтобы агент сам вызывал файловые инструменты, модель и API endpoint должны поддерживать function/tool calling. Чтение и поиск не показывают диалог подтверждения. Перед созданием папки, созданием файла или записью агент запрашивает подтверждение. Новый файл сначала создаётся пустым; операция записи работает только с уже существующим файлом. Все пути относительны к открытому проекту. Агент не получает командную строку или произвольный доступ к диску.

Подключённые MCP-инструменты управляются отдельно в панели MCP и не передаются AI-агенту автоматически.

## Папки и хранение данных

При запуске рабочим проектом становится `Документы/NotCode По умолчанию`; приложение создаёт эту папку, если её ещё нет. Через кнопку проекта в верхней панели можно открыть другую папку. Файлы сохраняются внутри текущего проекта.

История диалогов и настройки приложения хранятся в SQLite в каталоге данных приложения. Диалоги привязаны к проекту. API-ключ хранится отдельно в Windows Credential Manager.

## Структура исходников

```text
NotCode Desktop/
├── src/                         Интерфейс React и TypeScript
│   ├── App.tsx                  Сборка основного окна и состояние проекта
│   ├── components/              Редактор, проводник, AI, терминал, Git, MCP, настройки
│   ├── lib/                     Вызовы Tauri, типы, провайдеры AI и вспомогательная логика
│   └── styles/                  Стили интерфейса и CSS-токены
├── src-tauri/
│   ├── src/                     Rust-команды и системная логика
│   ├── icons/                   Значки desktop-приложения
│   ├── tauri.conf.json          Настройки окна, безопасности и установщика
│   └── Cargo.toml               Зависимости и параметры Rust-сборки
├── public/                      Логотип и шрифты
├── design-system/tokens.json    Исходные токены дизайна
├── scripts/                     Сборка Windows и генерация токенов
├── tests/                       Node-тесты вспомогательной логики
└── package.json                 Команды и JavaScript-зависимости
```

Основные Rust-модули:

| Файл | Назначение |
| --- | --- |
| `src-tauri/src/lib.rs` | Запуск приложения, создание состояния и регистрация команд Tauri |
| `src-tauri/src/project.rs` | Проекты, дерево файлов, поиск, чтение и запись в пределах проекта |
| `src-tauri/src/agent.rs` | Связь с AI API, потоковые ответы и файловые инструменты агента |
| `src-tauri/src/store.rs` | SQLite: проекты, диалоги, сообщения и настройки |
| `src-tauri/src/terminal.rs` | Локальный терминал через PTY |
| `src-tauri/src/git.rs` | Git-команды и операции с репозиторием |
| `src-tauri/src/mcp.rs` | Подключение локальных MCP-серверов и вызов их инструментов |
| `src-tauri/src/state.rs` | Общее состояние приложения и блокировки операций |

## Защита файлов и процессы

Файловый агент ограничен открытым проектом и не может обращаться к путям за его пределами. Из обхода проекта и поиска исключены `.git`, `node_modules`, `target` и `dist`. Чтение файлов отправляет их содержимое выбранному AI-провайдеру.

PowerShell и MCP запускаются с правами текущего пользователя Windows; ограничения NotCode не являются системной песочницей для этих процессов. Запускайте только доверенные команды и серверы. Перед сменой проекта остановите генерации, закройте терминалы и отключите MCP-серверы.

## Разработка и сборка

Для Windows-разработки нужны Node.js 22 или новее, Rust stable с MSVC toolchain, Visual Studio Build Tools с компонентом C++ для desktop, Windows SDK и WebView2 Runtime.

```powershell
npm install
npm run desktop:dev
```

Сборка Windows-приложения и NSIS-установщика:

```powershell
npm run desktop:build
```

Установщик появляется в `src-tauri/target/release/bundle/nsis/`.

Полезные команды:

```powershell
npm test
npm run tokens:check
npm run tokens
```

## Технологии

- **Tauri 2 и Rust** — desktop-окно, файловые операции, SQLite, терминал, Git и MCP.
- **React и TypeScript** — интерфейс и состояние приложения.
- **Monaco Editor** — редактор кода.
- **xterm.js и portable-pty** — интерфейс и системный PTY-терминал.
- **SQLite** — локальная история диалогов и настройки.
- **Ollama или OpenAI-compatible API** — AI-провайдер.

Приложение остаётся MVP: в нём одно основное окно, нет системы расширений редактора и восстановления вкладок после перезапуска. Прямая интеграция Codex App Server и Claude Code не реализована.
